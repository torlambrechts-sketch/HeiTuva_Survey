## The three decisions, as they appear in the schema

**Q119 is an absence in the migration and a property in the tests.** No `default_*` column exists,
and the suite asserts `workspaces` has no column matching `default|threshold|anonym|policy|pack|
retention`. Stated as a property of the table rather than a list of columns I chose not to add, so
a later phase that adds one fails here rather than racing `M:0032`'s pack lock.

**Q122 is D161.** The org default is a column; the per-person choice is a cookie. Not a preference
between mechanisms — `localStorage` is not readable at server render and Oversikt is a server
component. The suite asserts `org_members` has no `workspace` column, so the absence is checked.

**Q124 is `M:0049:22`'s column verbatim.** `preset_key references dashboard_presets(key) on delete
set null`, with the mapping pinned: `hr→Arbeidsmiljø`, `cx→Kundeopplevelse`,
`quiz→Medlem og frivillig`, and Tilpasset's NULL rendering the other sentence.

**The FK is `no action deferrable initially deferred`, not RESTRICT**, with the reasoning beside it.
Nothing deletes a shipped registry row today, so the two behave identically — which is exactly when
the choice is free to make.

## The finding: the non-vacuity guard caught its own author

CI's first run of the suite failed on exactly one test, and it was the guard:

```
× nobody may WRITE workspace_module_links through the API
  → workspace_module_links has a row to try to change: expected undefined to be 1
```

**The bug was an enumeration and it was mine.** The test did `select('key')` across all three
tables and inserted `{ key: … }`; `key` is a column on two of them, and
`workspace_module_links` is keyed `(workspace_key, module_key)`.

**What the guard bought is the whole argument for writing them.** The insert would have been
refused anyway — for an unknown column rather than a missing policy — and the test would have
PASSED while proving nothing about the policy it is named after. That is D158's shape, on a suite
where no Docker meant no red-first run to catch it instead.

**Fixed as the property, not as a better-guessed row**: *no policy on these tables permits anything
but SELECT*, read from `pg_policy`. Catalogue-derived, uniform across the three tables, independent
of a row's shape — the thing I got wrong. Same discipline as enumeration row 9.
