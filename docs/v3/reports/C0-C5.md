## 1. Per phase

### C0 — the bundle installed, and its copy swept

Seven-item checklist, each item **checked** rather than intended: `git status artifacts/` showed the
35 PNGs; `eslint --no-ignore` over the new bundle reports 11 errors in its own `support.js`, proving
the `.eslintignore` line is load-bearing.

**Three fields in the reference harness were enumerations of the bundles that existed** (D157), and
v3 broke all three. `Screen.only: ['v2']` was the costly one: v3 contains all eight of those
screens, and the filter would have withheld every one from the set they are the target for — eight
missing PNGs, no crash, the «green for something that structurally could not be seen» shape. It is
`since` now.

**The sweep found six things** (`03-c0-sweep.md`). The sharpest: `qcHint` — «Lederen kan svare uten
å se hvem som skrev» — is rendered **unconditionally**, including on a survey whose own mode
description is «Navnet følger kommentaren». The most important is an ABSENCE: nothing in the bundle
tells the respondent a comment is read as it stands, while the k-anonymity banner sits directly
above the comment box.

**D156** came out of trying to photograph a state: `respondList` emits no `id`, so all five of the
bundle's `qcSaved` reads key on the string `"undefined"` and the per-question comment has one slot.
That makes «Et valg per kommentar» false against the bundle's own behaviour — and **corrects
`00-diff.md § 4.2`, which read a storage shape as a behaviour.** Q113 is therefore a copy
correction, not a behaviour override; the weaker claim is the true one.

### C1 — the comment table, the token capability, the column

**The step that paid for itself.** Run 124 carried the tests and no migration: **21 failed, 1046
passed.** Twenty-seven tests, six passed — two legitimately (catalogue sweeps for a reader that must
never appear), and **four were claims wearing a check's clothes** (D158). All four asserted over an
empty result: a null payload stringified to `"null"`, a loop over zero rows, `[] toEqual []`, an
`.error` read off `null`.

Test 18 is the one that stings: Gate 5a3 separates PROTECTED from PROVEN precisely so an empty table
cannot pass a cross-org read check — *«the fixture, not the policy, would be doing the work»* — and
I wrote a test that did exactly that, in the phase whose subject is the policy.

**`survey_comments` does not reference `responses`.** The first draft carried both a `response_id`
and an `invitation_id` so a test could compare anonymity. Written out, that pair is a join from an
invitation to a response — the link the anonymity CHECK exists to forbid. The table built to protect
invariant 2 would have defeated it through the side door.

**One bug found by re-reading my own diff:** `(v_comment->>'question_id')::uuid` cast a client string
straight to uuid, so a malformed one would raise inside the transaction and lose the respondent's
real answers — while the comment directly above it claimed that protection. A defence that existed
only in prose, in a migration written to a rule about defences.

**Fix pass:** run 34577625954, 4 failed. All four mine, all four real — `one()` returning the first
LINE of psql output (so every `not.toMatch` over a function body was reading a 37-character
signature fragment), and a fixture that asserted RLS with persona clients against an org they do not
belong to. Standing question 2b, verbatim.

### C2 — the Builder control

### C3 — the respondent surface

**Two text boxes now sit on one question card with different protections**, and the bundle draws
both and distinguishes neither. `answers.comment` is an ANSWER: in the vault, k-gated. The comment
is a MESSAGE: outside it, not k-gated at all. Each says what it is.

Q112's sentence ships, asserted to differ from every banner string and asserted not to carry a
number or a «først når» — «anonymt» and «ingen kan lese det du skrev alene» are two promises, and a
banner making the first over this box would be technically true and materially misleading.

**D159:** the end-of-survey box moves from the thank-you screen to the last step. By the time that
screen renders, `responded_at` is set and a second call is `already_responded` — Q111 property 2,
untouched. Sending from there needs a second write path, and invariant 2 says there is one. A
fidelity cost and a correctness gain: a respondent who closes the tab now loses nothing.

### C4 — one surface, one filter

The rail that was the task filter moves down under its own heading; the top-right rail becomes
Alt / Oppgaver / Tilbakemeldinger. `M:0101` gives `handled_at` its writer — a function rather than an
UPDATE policy, because the table has none by design and widening it would open `body` with it.

**D160:** four of the bundle's six row tags are not built (no classifier, and a `tag` column would
have been the standing question's fifth instance), and «Lag oppgave» is rendered **disabled with a
reason** rather than hidden, because behind it is Q72 — the task register is readable in full by a
`leser`, and a task made from a comment carries a respondent's own words into it.

## 3. Decisions I defaulted, listed so they are findable

All in `docs/v3/01-decisions.md`.

| | | reversing it costs |
|---|---|---|
| **Q115** | anonymous comment → any member; **named** comment → administrator/redaktør only | one `using` clause **and a change to invariant 4** |
| **Q116** | no `tag` column; two chips derived, four not built | a migration plus a classifier |
| **Q117** | the reply is its own table, not jsonb | a migration |
| **Q118** | `get_comment_thread` is anon-executable and therefore allowlisted in 5a3 | see below — **this one diverges from an instruction** |

**Q115 is the one to read.** Q114's second condition says a verneombud reads the thread «on the same
footing as the rest of the documentation». There is no verneombud ROLE — it is an assignment — so
«the same footing» can only mean the rules that already exist, and the rule that already exists is
invariant 4: a `leser` gets **no named free text, anywhere**. Widening to `is_org_member` alone
would hand every leser named free text, which is a security-invariant change and not a policy tweak.

**Q118 is the divergence.** Tor: «if either the table or the read RPC lands allowlisted, the phase
has not closed.» **Both tables land CHECKED.** The RPC cannot: Gate 5a3 judges a definer function by
`!grantedToAnon` alone and has no «checked and anon-granted» state, the apparatus is frozen, and a
respondent holds a link and never a session. The only way to satisfy the letter would be to revoke
the grant and call it with the **service-role key from the respondent server action** — a key that
bypasses RLS entirely, on the one surface reachable by anybody holding a URL. That is a real
weakening bought for a metric, and I did not take it. It is allowlisted the way this project
allowlists things: with a reason whose every clause has a test.

## 4. What is now possible in the product that was not

- **A respondent can say something in her own words, on a specific question, and be answered** —
  through the same link she answered from, with no account and no second credential.
- **A manager can reply without learning who wrote it.** In `anonymous` mode the thread carries no
  name to any screen, and the reply reaches her because the invitation scopes the thread rather than
  identifying a person on screen.
- **An organisation can turn the whole channel off, per survey**, and every survey that existed
  before this tranche is off — not because nobody switched it on, but because the migration
  deliberately backfilled it that way.
- **A statutory kartlegging can carry a thread** (Q114), with a comment never a precondition of
  submitting and a verneombud reading it on the footing a `leser` reads everything else.
- **Oppgaver and Tilbakemeldinger are one surface with one filter**, so a finding and the action it
  produced are not two screens apart.

**And one thing that is now impossible that was not before:** a comment cannot be joined to the
answers submitted with it. There is no `response_id` on `survey_comments` and no column named like
one, asserted over the catalogue.

## 5. What I would not conclude

- **Not that any of this has been seen.** Docker is unavailable in this session, so **every visual
  half of every phase is UNVERIFIED**. No screen in C2, C3, C4 or C5 has been opened by anything but
  the type checker and the tests. The one thing I looked at is a rendered *bundle* baseline
  (`artifacts/reference-v3/respondent-kommentar-lagret.png`), which is the design, not the product.
- **Not that C3 passed its browser gates.** It did not: run 34578939496's browser job was
  **cancelled by my own next push**, because the workflow's concurrency group is per-branch. The
  database gates and the static job were green on that commit; the browser half ran only on the
  superset that followed.
- **Not that the `off` backfill works.** A reset has no pre-existing surveys, so the property Tor's
  correction is about is unobservable at runtime. The test reads the migration's statement ORDER,
  which is weaker and is named as weaker.
- **Not that the remaining negative tests fail for the right reason in every state.** Run 124 proved
  they fail when the table is ABSENT. Four were audited for the present-and-empty case and fixed;
  the others were not.
- **Not that the copy is right, only that it is not false.** The claim-set sweep compares sentences
  against the database. It cannot tell whether «Kommentaren leses som den står» is the sentence a
  Norwegian employee actually understands, and that is a question for a person.
- **Nothing reached production.** Four migrations (`M:0099`–`M:0102`) exist in the repo and have run
  in CI. `supabase db push` was not run, and prod is four migrations behind on this branch.
