## 3. The three design decisions that are not obvious

### 3.1 `survey_comments` does NOT reference `responses`

The first draft carried both a `response_id` and an `invitation_id`, so a test could compare a
comment's anonymity against its own response's. **Written out, that pair is a join from an
invitation to a response — the exact link the anonymity CHECK on `responses` exists to forbid.**
The table built to protect invariant 2 would have defeated it through the side door, in the
migration whose subject is that invariant.

There is no `response_id`. Q113's property — no named comment shares a `response_id` with an
anonymous answer — then holds because **no row has one**, which is stronger than any check over
values. Tests 12 and 13 assert it over the catalogue, so a column merely *named* like one fails
too.

### 3.2 The backfill is an ORDER, not a statement

`add column … not null default 'anonymous'` writes `'anonymous'` into every existing row, and a
backfill after it is a no-op on exactly the rows it was meant to fix. So: add nullable, backfill
`'off'`, then set the default, then `not null`.

**A limit, stated rather than papered over.** `supabase db reset` runs the migration against an
empty schema, so at backfill time there are no surveys and the effect is unobservable at runtime —
in CI and on a fresh local stack alike. Test 23 therefore reads the MIGRATION and asserts the
order. It is a weaker check than a row assertion and it is named as one.

### 3.3 `submit_response`'s signature widens, where `M:0087` refused to

That refusal was right for `elapsed_ms`: a timing is per-answer data and fits inside `p_answers`.
**A comment does not.** The end-of-survey comment belongs to no question and has nowhere to live in
a map keyed by question id; a reserved key would collide with a real uuid the day someone generates
one. The four references `M:0087` named — invariant 2, the 5a3 allowlist, `verify:attack`, the
`test-mode` sweep — were re-checked rather than assumed unaffected. All four address the function
by NAME, not by arity, so none needed an edit; the positional 5-argument calls in
`tests/db/test-mode.test.ts` still resolve, because the old signature is dropped and the sixth
parameter has a default.

## 4. `feedback_mode` was decorative for an hour, and that was a defect

The first write path ignored it entirely: `p_comments` was written whenever it was present. **A
hand-rolled client can post anything, so a mode enforced only in the UI is not enforced.** It is
now checked where the write happens.

Dropped rather than refused — refusing the whole submission would lose real answers over a field
the respondent never saw, which is `M:0087`'s reasoning about an out-of-range stopwatch. **Not
silently**, though: the payload returns `comments: <count written>`, so a client that sent two and
is told `0` knows why. A drop with no report is the shape a catch-all makes.

## 5. And one bug found by re-reading my own diff

`(v_comment->>'question_id')::uuid` cast a client-supplied string straight to `uuid`. **A malformed
one raises inside the transaction and loses the respondent's real answers** — while the comment
directly above it claimed exactly that protection. A defence that existed only in prose, in a
migration written to a rule about defences. Guarded by shape now; test 28 sends `'ikke-en-uuid'`
and asserts both that the submission survived and that the comment was stored with no question.

## 7. What I would not conclude from this phase

- **Not that the backfill works.** A reset has no pre-existing surveys, so the one property Tor's
  correction is about is unobservable at runtime. Test 23 reads the migration's statement ORDER,
  which is a weaker check and is named as one.
- **Not that the remaining tests fail for the right reason in every future state.** Run 124 proved
  they fail when the table is ABSENT. A test can still be vacuous against a table that is present
  and empty; 18, 19 and 10 now guard that case explicitly and the others were not audited for it.
- **Not that the respondent surface works.** C1 built no UI. The write path is exercised by tests
  and by the seed, and by nothing a person has looked at.
