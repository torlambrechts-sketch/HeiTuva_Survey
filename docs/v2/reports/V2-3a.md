## 2. What this phase decided against its own plan, and why

**Two of the plan's schema lines were overturned by Q92 and Q64.** They are struck in
`03-plan.md` with a pointer here, rather than edited to read as though they had always said
something else.

### `groups gains kind` → a separate `segments` table

Q92 says a segment is a **filter, never a breakdown axis**, because **k does not compose**:
two segments of five answers with an intersection of two disclose the two by subtraction.
Q93 is promoted as *«closed by Q92 — the possibility is REMOVED rather than filtered at each
site»*. That sentence is only true if a segment is not a row in `groups`:

```
select p.proname from pg_proc p join pg_namespace n on n.oid = p.pronamespace
 where n.nspname in ('public','app')
   and p.prosrc ~ 'from\s+public\.groups|join\s+public\.groups';
-->  compose_report, get_heatmap, results_summary
```

All three iterate every group row in the organisation **unfiltered**. A `kind` column makes
correctness depend on three functions remembering a predicate, and on the fourth reader
remembering it too. **A separate table makes the leak unrepresentable**:
`responses.respondent_group_id` references `public.groups`, so a segment id cannot reach the
breakdown axis even by mistake. This is the structural-not-scheduling principle applied to
the schema.

### `round_audience_members` and `audience_events` → not built

Q64: the freeze **already holds**. `survey_invitations` is a per-round snapshot and the
denominator counts those rows. The proposal would have created a property that exists. What
was missing was a **test**, which is §3's blocker.

### The mutation round, and the one result that is not just a tally

Eight mutations, each caught by the test written to catch it. **One deserves separating
from the count**: a function joining `survey_invitations` to `org_members` — a path that did
not exist when the test was written — was caught **by name**. That is the catalogue
derivation working as designed rather than a test passing: the assertion enumerates
`pg_proc` and reports what it finds, so it fails for code nobody anticipated instead of for
the cases somebody listed. It is the difference between a check and a checklist.

The other seven: dropping the predicate validator (3 red) · widening `segments_ins` to any
member (1) · **adding `kind` to `groups`** (1 — it fails the moment someone starts down the
road the plan originally described) · reverting Q94 (1) · stubbing the xlsx sniffer (2) ·
rule 1 regrowing its own comparison (2) · hard-coding 5 as all four bundle surfaces do (3).
