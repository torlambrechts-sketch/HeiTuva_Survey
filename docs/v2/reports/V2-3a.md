## 2. What this phase decided against its own plan, and why

**Two of the plan's schema lines were overturned by Q92 and Q64.** They are struck in
`03-plan.md` with a pointer here, rather than edited to read as though they had always said
something else.

### `groups gains kind` → a separate `segments` table

Q92 says a segment is a **filter, never a breakdown axis**, because **k does not compose**:
two segments of five answers with an intersection of two disclose the two by subtraction.
Q93 is promoted as *«closed by Q92 — the possibility is REMOVED rather than filtered at each
site»*. That sentence is only true if a segment is not a row in `groups`:

```
select p.proname from pg_proc p join pg_namespace n on n.oid = p.pronamespace
 where n.nspname in ('public','app')
   and p.prosrc ~ 'from\s+public\.groups|join\s+public\.groups';
-->  compose_report, get_heatmap, results_summary
```

All three iterate every group row in the organisation **unfiltered**. A `kind` column makes
correctness depend on three functions remembering a predicate, and on the fourth reader
remembering it too. **A separate table makes the leak unrepresentable**:
`responses.respondent_group_id` references `public.groups`, so a segment id cannot reach the
breakdown axis even by mistake. This is the structural-not-scheduling principle applied to
the schema.

### `round_audience_members` and `audience_events` → not built

Q64: the freeze **already holds**. `survey_invitations` is a per-round snapshot and the
denominator counts those rows. The proposal would have created a property that exists. What
was missing was a **test**, which is §3's blocker.

## 4. DEFECTS

*Three found by gates that had never run on this code, and two the gates cannot see.*

### 1 — MAJOR, FIXED. The rule builder's chosen-field state was never photographed

`tests/routes.manifest.ts:360`. The scenario reached for `page.locator('select').first()`,
which resolves to **the shell's language switcher** — an `opacity-0` overlay `<select>` that
Playwright correctly reports as never visible. Both viewports spent thirty seconds waiting
for it and `regel-felt-valgt` was captured on neither.

**What makes it a major rather than a nuisance**: the rule builder in its active shape — a
field chosen, the operator and value controls live — was in no capture at all, and §8 cited
a screenshot that did not exist. This is CLAUDE.md's «a visual gate that had only ever
photographed the old state», in its loud form: it failed instead of photographing the wrong
thing, which is the only good news in it. **A positional selector on a page with persistent
chrome is a selector aimed at whatever loads first**, and the panel's controls have had
proper `aria-label`s all along.

*(What that state does NOT show is defect 4, and I only learned it by opening the picture.)*

Fix: `getByLabel(/^(Velg felt|Choose a field)$/)`. The manifest was swept for the class —
`locator('select')`, `locator('input')`, `locator('button')`, `locator('textarea')` — and this
was the only bare positional one; the remaining `locator('textarea')` is scoped by a `form`
filter. Evidence: `fix1.log:38-39,121-122`, both viewports `ok`.

### 2 — MAJOR, FIXED. `segment_fields` shipped without a denial test, and took thirteen gates with it

`verify:policy` refused the new table and `verify:all` exited at gate four of seventeen. This
is in the gate-state table as a fact rather than here as an apology: **the gate did exactly
what it is for**. Fix: an allowlist entry carrying its reason, and the table CHECKED rather
than trusted — `tests/db/segments.test.ts:185` asserts the public registry has no column
matching org/survey/count/user/email.

### 3 — BLOCKER, FIXED. `admin-malgrupper` was the only screen in the app with horizontal scroll at 320px

`scrollWidth=385` against `clientWidth=320`, both states; **every other screen in the app
measured exactly 320**. Three causes, and they were measured rather than guessed at, because
a 65px overflow has more plausible causes than real ones:

| | width | cause |
|---|---|---|
| threshold badge | 340px | «Under virksomhetens terskel (5) — resultater vises ikke» under `whitespace-nowrap`. The group card's copy of the same badge already wrapped |
| field `<select>` | 304px | a `<select>` takes its intrinsic width from its **widest option**, and «stillingsprosent — ikke tilgjengelig ennå» is it. **Q65's own «say so» copy set the page's minimum width** |
| card grid | 280px | `minmax(280px,1fr)` is a floor, not a preference |

**And the first fix was not the whole fix, which is the part worth keeping.** After all three
the re-run reported **369, still over** — because a `<fieldset>` carries a UA
`min-inline-size: min-content`, so the select's widest option propagated up through it and
`max-width:100%` was already being measured against a grown parent. Isolated in Chromium at
320px, four variants, `scrollWidth` each time:

```
bare                           357
max-width:100% on the select   357
+ min-width:0 on the select    357
+ min-width:0 on the FIELDSET  320
```

Either `min-width:0` alone changes nothing. **A fix that moves a number without reaching zero
is a fix aimed at a symptom**, and re-measuring rather than assuming is what turned 369 into
the fieldset. Every part of the fix is inert at ≥1280px — `md:whitespace-nowrap`,
`min-w-0 max-w-full`, `min(280px,100%)` — so the desktop rendering the bundle governs is
unchanged, which is the only form of this fix CLAUDE.md's pixel rule permits.

RESPONSIVE.md's rule for all of it is one sentence: «Remove the width constraint and let the
existing `flex-wrap` do the work.»

### 4 — MAJOR, FIXED. I cited a screenshot for a clause a screenshot cannot show

Found by doing what Gate 3a actually asks — opening
`artifacts/phase-1/admin-malgrupper.regel-felt-valgt.desktop.png` and looking at it, rather
than reading «ok» in the capture log and moving on.

**A native `<select>` never shows its options in a screenshot.** The dropdown is drawn by the
operating system, outside the page. So the state renders `rolle` in a closed control and
that is all it can ever render: `stillingsprosent — ikke tilgjengelig ennå`, the whole of
Q65's «the editor must say so», is in the DOM and nowhere on the picture. §8's citation for
that clause was a file that exists, opens, and is silent on the thing it was cited for.

**This is the project's own recurring shape one more time — evidence that is present and
misattributed.** Defect 1 was the loud version, where the gate errored; this is the quiet
one, where everything is green and the citation is simply about something else. Nothing in
the apparatus could have caught it: the capture succeeded, the pixel diff passed, the log
said `ok`.

Fix: the clause is asserted where it can be, in `verify:interaction` (Gate 3c) — the
unavailable fields are **offered** rather than omitted, each carries «ikke tilgjengelig», and
at least one other field is selectable, all read off `select[aria-label="Velg felt"]`'s
options. The screenshot keeps its job, which is the rule builder's active layout. §8's row
now cites the assertion, and says why the picture is not the evidence.

### 5 — MINOR, NOT FIXED, LOGGED. The database tells two refusals apart; the screen does not

`actions.ts:57-60` maps both `segment_field_not_allowed` and `segment_field_unavailable` to

### 7 — MINOR, FIXED. «1 personer»

Visible in the same screenshot, on the Ledelse card. `mgPeople` was `"{count} personer ·
{source}"` with no ICU plural, in a file where `groupCount`, `readyCount`, `sentTitle` and
`channelSummary` all have one. Both languages fixed
(`{count, plural, one {# person} other {# personer}}` / `{# people}`). A one-person group is
the ordinary case on a small team's first audience, so this is the first thing a new customer
would have read.

### 8 — MINOR, JUSTIFIED. Five `as never` casts

`lib/audiences/segments.ts:70-82`. The Supabase query builder types its value argument off the
column *literal*, and the column here is `field.source_column` — a registry string, unknown at
compile time. **The cast weakens the type of the VALUE only.** The column name never comes
from user text and the value goes through as a bound parameter, so nothing about injection
changes; a wrong-typed value makes PostgREST refuse, `countSegmentMembers` returns `null`, and
the row renders «antall kan ikke beregnes» — the designed path, not an accident.
No other `any`, `as unknown as`, `@ts-ignore` or non-null assertion was added this phase.

## 7. Environment events, and why they are environment events

**The local Docker daemon died three times during this phase**, each time taking the Supabase
stack with it. Recorded here rather than left as folklore, because the failure mode is
indistinguishable from a data-quality problem until someone checks which it is.

| # | What it looked like | What it was |
|---|---|---|
| 1 | `npm run verify:policy \| grep -c '^  ok '` returned **0** while writing D110's own commands | Docker gone; the gate could not reach the stack |
| 2 | `psql … select 1` refused mid-phase while reading `send_round` | Same. `send_round` was read from the migration file instead — where the definition lives anyway |
| 3 | `seed:demo` failed with `TypeError: fetch failed` | Same. Restarted, re-seeded, re-ran |

**NOTHING IN THIS REPORT WAS PRODUCED BY A DEAD STACK.** Each time the daemon was restarted,
the stack brought back up, the data re-seeded, and the command re-run before any number was
written down. **This is D110's case 2 in practice, three times** — «the command cannot run;
the number may still be correct; fix the environment and re-run BEFORE touching the
document». The first instance is the one that nearly put an asserted number inside the entry
demanding measured ones.

**The discipline is what keeps this an environment fact rather than a data-quality one.** A
zero from a dead stack recorded as a measurement would be indistinguishable, six months on,
from a real regression — and the reader would have no way to tell which they were holding.
