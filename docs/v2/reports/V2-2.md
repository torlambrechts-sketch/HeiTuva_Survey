## 2. What this phase decided, and on whose authority

Three decisions landed together because they are one rule seen from three sides.

| # | Decision | Authority | Where it is enforced |
|---|---|---|---|
| **Q90** | `organizations.default_k_threshold` is a **FLOOR**, waived only by `privacy.redaktor_may_lower` | Tor, on the flag's own evidence | `app.guard_survey_policy` raises `below_org_floor` (`M:0054`) |
| **Q58** | ONE pack key carries a locked policy — `trakassering-ytringsklima`, 8/anonymous/person; and `apply_pack_policy` takes `greatest(pack, org)` | Tor | `M:0054` + `supabase/seed.sql` |
| **Q91** | The floor moves **3 → 2**, superseding Q17's floor | Tor | `M:0055` — `k_threshold >= 2 or respondent_kind = 'organisation'` |

**Q90 was not decided on say-so, and the distinction matters because a floor is a security
bound.** `privacy.redaktor_may_lower` has existed since `M:0034` and is *meaningless without a
floor to lower beneath*: the global floor is a CHECK, and a CHECK cannot be granted or withheld
by permission, so «lower» had no referent unless the organisation's value binds. The reading
was already in the schema by the flag's own existence; what was missing was the constraint the
flag is an exception to.

**The absence it corrected was ENUMERATED, not read for.** `scripts/verify/threshold-readers.ts`
derives every reader and writer of both threshold columns from `pg_proc`, `pg_constraint` and
`pg_trigger`, classifies each as BOUNDS / SEEDS / READS, and before `M:0054` returned:

```
VERDICT: 0 surface(s) constrain a survey's threshold against organizations.default_k_threshold.
  The column SEEDS and does not BOUND. Any copy promising an organisation-level
  floor for individual surveys is describing behaviour that does not exist.
```

and now returns `1`. That is the answer to Tor's instruction *"do not ship copy asserting an
absence you cannot demonstrate"* — and its mirror: the copy that now asserts the floor is
demonstrable by the same script.

**Q17 is left intact with a pointer forward.** The register's header permits correcting a
decision that MISDESCRIBES THE WORLD; this is not that. Q17 described the product accurately
and a product bound was changed deliberately. A register that rewrites its own history cannot
show that a bound moved — which is exactly what `docs/LEGAL_DRAFTS.md` now needs it to show.

**Defect 6 is the important one and it is not about translations.** The state was defined
relative to an ordering nobody owns, and it WROTE. It had been harmless for as long as the key
it happened to land on was inert — which is not a property anyone was maintaining, and stopped
being true the moment a phase added messages to the `admin` namespace. Standing question 4,
*what does the test leave behind*, catches it exactly; nothing in the apparatus asks that of a
capture setup.

**Defect 8 is the interesting one, and it is about the gate rather than the header.** V2-0 and
V2-1 both reported READY FOR REVIEW while `verify:visual` had never executed — it refuses to
run with a missing browser, which is right, but a gate that cannot run is not a gate that
passed, and neither report said so. **The apparatus behaved correctly and the reporting did
not.** What made it visible was installing the browsers, not reading the reports.

**Defect 7 is the harness working.** `verify:responsive` distinguishes «measured and fine» from
«could not be measured» and calls the second a blocker. A gate that scored an unreachable state
as a pass is the failure mode this whole apparatus exists to avoid.

**Defect 3 is the one worth keeping.** Three other mutations on the same migration were caught
first time — widening the logo INSERT policy, making its SELECT org-blind, making the trigger
fire on every update. The one that slipped through was not a weaker assertion; it was an
assertion whose SUBJECT was ambiguous. `tests/db/clients.ts` standing questions 2 and 4 name
this exactly, and reading the test did not find it. Only removing the control it claimed to
test did.

**Defect 2 generalises defect 1 of V2-1.** That one was a phrase list ageing into a symptom
catalogue; this one is the same disease one level up — an allowlist keyed by name ages exactly
like a phrase list, and an entry that can never fire reads as coverage. Both self-checks are
now derivable properties: *a reason claiming interpolation is verified against the string*, and
*an entry naming no message key is dead*.

made them. One sentence says the three are built with sending; **D108** records what and why.
They land with **V2-11**.

**Suppression and member state — the plan's own V2-2.** Not in this commit series. Tor's
instruction was «V2-2, with Profil's unblocked half folded in», and the three threshold
decisions arrived mid-phase and were larger than the plan allowed for. **The suppression list,
`send_round`'s refusal, the re-import case and the six negative tests are still owed**, and are
the next thing.

**The grandfathering count Q90 asked for.** Tor: *"report the count before deciding whether it
is grandfathered or raised."* Local counts (37 of 269 person surveys below their org default,
31 not yet locked, 0 statutory raised by the `greatest()`) are a database of fixtures and are
not the number that decision should rest on. **Prod could not be measured**: the Supabase MCP
server needs an interactive authorisation this session cannot run. The safe half was taken —
the constraint binds at WRITE time and rewrites nothing — and the count is owed before anyone
decides to raise existing rows.
