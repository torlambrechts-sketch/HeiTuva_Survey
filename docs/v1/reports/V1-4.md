### 1.3 Q51 — where the constraint lives, and what the test proves

Three constraints in `M:0046`, plus a fourth in `M:0048`. None in a server action: an
action is one caller and the table is writable through PostgREST — Q36's lesson applied
to a payload rather than a scalar.

| Constraint | What it forbids |
|---|---|
| `app.layout_keys_registered` trigger | a panel key that is not a registry row offered on the dashboard |
| `dashboard_layouts_panels_shape` | any key in a panel entry beyond `key` and `wide` |
| `dashboard_layouts_filters_shape` | any key in `filters` beyond `period`, `group_id`, `survey_ids` |
| `dashboard_layouts_preset_no_group` | an organisation preset carrying a group filter |
| `app.preset_title_free` (M:0048) | an organisation preset taking a shipped preset's name |

**The one that matters, in the words it was asked for:** *save at 5, raise to 8, replay,
assert 8.* `tests/db/dashboard-layouts.test.ts` saves a layout selecting a survey at
k=5, raises that survey to k=8, re-reads the STORED filters and calls the RPC with them.
The gate comes back 8, and the stored payload is asserted to contain no threshold that
could have gone stale.

Nothing in a layout can carry a k because k is computed inside the RPC on every call —
`max(app.k_for(s.id))` over the surveys in scope (`M:0032:973`, `M:0032:1043`) — and
`p_surveys` is a filter, never a widener.

Every constraint was **mutation-checked**: dropping each one fails exactly its own test
and nothing else.

### 1.4 Q51's other half — the part a CHECK cannot deliver

Tor's addition: explain it at the point of SAVING, not only enforce it. An administrator
with a group filter active who opens «Lagre dette som eget oppsett» is told, before
saving, that the group will not travel and that period and surveys will. `filtersForPreset`
is the one place that decides what travels, returns whether anything was dropped, and the
database refuses the row if the two ever disagree.

Without it the boundary is a correct refusal presenting as a silent surprise — the shape
this project keeps meeting.

### 1.5 Q26 and Q51 are the same mechanism

There is deliberately no `stream` registry row, so a layout naming it is refused by the
database — not by the picker, not by a seeded preset, not by a hand-written PostgREST
call. The flag is what the UI reads; the missing row is what the database enforces. A
test asserts they agree, and that **the flag alone changes nothing**: lifting Q26 needs
the migration first and the flag second.

## 2. Defects found and fixed

**Eleven.** Three by mutation, five by looking at captures, two by an audit, one by
Gate 3e. The distribution is the finding: **the gates found one of eleven.**

### By mutation (3)

1. **Two tests were proving the wrong policy.** `insert(...).select('id')` with an error
   assertion passed with `dashboard_layouts_ins` widened to `is_org_member` alone, because
   PostgreSQL applies the SELECT policy to an INSERT's RETURNING — the refusal came from
   `_sel` wearing a write test's name. A bare insert is **accepted** under the widened
   policy, measured directly. Rewritten to assert on the stored row.
2. **The delete test has the same confound and cannot be fixed the same way.** PostgreSQL
   requires SELECT to reference the columns in a DELETE's WHERE clause, so a colleague who
   cannot read the row cannot name it. Through PostgREST it is `_sel` that protects a
   personal layout; `_del`'s user check is defence in depth. Labelled **at the assertion**,
   so a failing run teaches the property rather than requiring archaeology.
3. **Nothing asserted that a colleague's PERSONAL layout is unreadable.** Every read
   assertion was about an org preset (meant to be shared) or an outsider (caught by org
   scope), so widening `_sel` failed no test.

### By looking at captures (5)

4. **The survey chips rendered TWICE** — in the card where Q46 puts them, and in the header
   row Q46 removes. Both locations individually correct. See § 5.
5. **`allGroups` was one key serving two strings** — «Alle grupper» as a select option,
   «alle grupper» inside the filter line. The select read lowercase mid-list.
6. **The seeded layout was the thin shape**, so the demo dashboard lost trend and heatmap
   and looked emptier after this phase than before it.
7. **`group` and `period` arrived twice** — as props and inside `layoutFilters`. Removed
   rather than underscore-prefixed.
8. **Two chips both named «Arbeidsmiljø»** — a shipped preset and an org preset can
   collide, and `dashboard_layouts`' unique index structurally cannot see
   `dashboard_presets`. Now `M:0048`, scoped deliberately to org presets, mutation-checked.
   The demo seed created the collision, and the constraint now refuses the seed.

### By auditing decisions against code (2)

Neither was reachable by any gate, because a gate checks what exists rather than what a
decision required.

9. **Q26's absence was HIDDEN, not DRAWN.** I built the refusal and stopped. The decision
   says more: «the panel appears in the picker as the bundle's own unavailable state, with
   its `req` chip. The bundle sanctions drawing its absence, so this is not hiding a
   feature.» A panel nobody can see is not deferred; it is missing. Now drawn greyed with
   its precondition, added by the picker rather than seeded as a row — a row is what a
   layout may name and this must stay unnamable.
10. **«Frys som rapport» did not exist.** Q29 keeps «Åpne rapport (n)» BESIDE it, and the
    two answer different questions: the opener reads the PINS (what I chose to keep), the
    freeze reads the LAYOUT (what I am looking at). Only the first was built.

### By Gate 3e (1)

11. **228 blockers, one cause.** Five 30px controls with 44px hit areas overflow 7px each
    side; the design's 6px gap therefore overlapped by 8px². `.touch-cluster` sets 14px
    inside the same `max-width: 767px` block that creates the overlay, so the design's 6px
    is untouched above `md` where no overlay exists. See § 4.

One more caught before CI could: the seed assertion said `sections = 11` and the registry
now holds 12. Corrected and extended with `presets = 6` and `panels = 6`, the second being
the vocabulary a layout may name — which must not include `stream` while Q26 stands.

## 3. Deviations and structural calls

**D100** — «Kundeopplevelse» and «Intern tjenestekvalitet» seeded without the stream
panel, **and their descriptions changed**: copy promising «løpende» beside a preset that
cannot show it is the fabricated-data rule one level up. Enforced by the same trigger that
guards a user's layout, so Q27 is a constraint rather than a memory.

**D101** — the first-run preset cards carry no illustration. The bundle's seven SVGs are
keyed by array POSITION, so a member's own preset would land on whichever drawing its
index selected. Ornament omitted deliberately; the honest form (one per preset KEY) is
stated.

**One registry, two flags — confirmed by Tor.** `report_section_types` gained
`on_dashboard` and `in_report` rather than the project gaining a second registry, because
two registries would need a rule for what happens when the same concept appears in both
and there is none: `heatmap` is the same heatmap in a report and on a dashboard. Four call
sites now ask for their subset. Measured, as asked: **no row has both flags false today**,
and a test refuses an unlisted one — not a CHECK, because "awaiting a consumer" is a
legitimate state a constraint would forbid.

**The label source made single.** The registry's `label` and next-intl held the same six
strings, agreeing by coincidence — which is how one gets translated and the other does
not. The registry stays the VOCABULARY, next-intl the NAME keyed as `panel_<key>` /
`desc_<key>`. Reading the registry's label instead would make every panel Norwegian in
English, which is what Q48(b) is for. **That decision line now records that V1-4 built a
working instance of the mechanism it describes**, and that the first question when it is
scheduled is whether it EXTENDS this rather than inventing an overlay.

## 5. The finding of this phase

The survey chips rendered twice: once inside the «Tilpass» card where Q46 puts them, once
in the header row Q46 removes. Both locations were individually correct — the chips
toggled the selection and carried the right state in each. Every test passed, and every
test would still have passed with a third copy.

**Duplication is invisible to assertions that check PRESENCE rather than COUNT**, and
almost every assertion a suite contains checks presence. `getByRole`, `toContain`,
`toBeVisible`, a selector that takes the first match — all are satisfied by two. A test
that would catch it has to say "exactly one", which nobody writes without a reason, and
the reason only exists after the second copy does.

This is the **fifth** instance in `VERIFY.md`'s Gate 3a evidence, and the cleanest: the
others were a true thing rendered misleadingly, a true thing not rendered at all, and a
control confidently describing the wrong state. This one is a true thing rendered twice.
