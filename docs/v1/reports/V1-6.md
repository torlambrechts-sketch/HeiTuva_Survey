## 4. Defects found and fixed

Nine. **Two were in the application, and they are the first application defects a
verification pass has found since V1-2.** Both came out of one failing assertion.

**Found while building (four):**

1. **Stale generated types.** `types/database.ts` did not carry `organizations.timezone`
   after `M:0051`, and `tsc` was clean because nothing read it yet. Fixed by amending
   `de2ec25` rather than adding a commit, because a half-generated type file is not a
   state worth having in history.
2. **A revoked function called from a trigger that is not `SECURITY DEFINER`.**
   `app.local_send_at` was revoked from `authenticated`, and `app.resume_schedule` runs as
   the caller — `permission denied for function local_send_at`. Granted to `authenticated,
   service_role`. **The test made this harder than it was:** it did not check the error on
   its own `update`, so a permission failure arrived as an unexplained wrong value three
   assertions later.
3. **A sweep too narrow to find its own bug.** The `next_run_at` derivation required
   `send_at_local` to appear in the function body, so it swept only functions that already
   knew about the column and missed the two that ignored it entirely. Widened to *every
   assignment to `next_run_at` goes through the helper*. **The general form, which is the
   part worth keeping: the derivation must describe the PROPERTY, not a symptom of it.**
4. **Backticks inside a JS template literal** silently truncated a SQL comment being
   generated. Removed.

**Found by the verification pass (five):**

5. **Q49's user-visible half was never built.** `M:0050` shipped `n` on a gated point;
   `TrendPoint`'s union still said the gated arm had no count (`lib/results/types.ts`),
   `results.roundsBelow` was the fixed string «under terskel», and `RoundsPanel` rendered
   it. **`tsc` was clean throughout, because nothing tried to read the field the database
   had started returning.** The decision says *«The panel renders the count beside «under
   terskel» instead of an em dash»* and it did not. **APPLICATION.**
6. **The count on a gated point was the wrong count.** `get_trends`' stats CTE counts
   responses **joined to `answers` on scale-type questions with a numeric value** — the
   right denominator for an average, the wrong one for participation. `coalesce(st.n, 0)`
   therefore reported **0 for a round four people answered**, if those four skipped the
   scale question. Zero is the worst available wrong answer, because it is the same number
   this function uses for "nobody took part". Fixed in `M:0053` by counting participation
   in its own CTE — which also makes `n` mean one thing across `get_trends`,
   `results_summary` and `overview_activity`, where before a single-round survey could put
   two different counts for the same round on the same screen. **The gate did not move:**
   `avg` is still protected by the count of people actually behind it. **APPLICATION.**
7. **A stale assertion from D94.** `attributed-results.test.ts:568` asserted the pre-Q49
   shape — `expect(point!.n).toBeUndefined()`. It failed, it was right to fail, and it is
   the only reason 5 and 6 were found. § 5.
8. **`M:0050`'s own comment asserted something false**, in as many words: *"a round the
   filtered group did not answer has no stats row at all … 0 is a true count of people"*.
   True only when the missing stats row means nobody responded. `M:0053`'s comment quotes
   the false sentence rather than deleting it.
9. **`RoundsPanel`'s docstring carried a claim Q49 had already corrected** — that emitting
   the count "means a third entry in Q28's enumerated exemption list". Q49's own correction
   settled that a month of work earlier, in `DECISIONS.md`, and the file never heard.

## 5. The finding of this phase

**The nearest miss yet to the case Tor asked me to watch for.**

V1-5 § 8.4 closed the "four of five defects were in the tests" observation with a rule:
*the thing to watch is not the ratio, it is whether a test defect ever MASKS an
application defect.* This phase produced the first candidate, and it is worth reading
closely because the masking version and the actual version differ by one question.

The failure was:

```
FAIL tests/invariants/attributed-results.test.ts
  > get_trends: a round nobody answered is a refusal too
  AssertionError: expected +0 to be undefined
```

**The mechanical reading is available, correct-looking, and wrong.** V1-6 changed the
gated point's shape on purpose; a test asserting the old shape is stale; the fix is to
update it to `expect(point!.n).toBe(0)`. That change is one line, it is green immediately,
it cites the decision that justifies it, and it would have shipped **both** application
defects: the denominator that reports 0 for four people, and a decision whose panel was
never built. The stale assertion would have masked them — not by being wrong, but by being
*repaired too quickly*.

**What prevented it was one question with no test behind it: what does `st.n` actually
count?** Reading the CTE answers it in four lines — it joins `answers`, so it is not the
round's response count — and from there the missing UI follows immediately, because the
next question is "what does the panel do with this number", and the answer was nothing.

So the rule this phase adds, and it is narrower than "be careful":

> **A test that fails because YOUR OWN change altered the contract is not a stale test. It
> is the only reader that noticed the contract moved.** Before updating it, say out loud
> what the new value MEANS — not what it is. A stale-test fix that does not survive being
> stated in words is a defect being written down as an expectation.

The related observation, and the reason the decision-conformance section stays worth its
cost: **it would have caught defect 5 independently.** Writing § 2 requires quoting *«The
panel renders the count beside «under terskel» instead of an em dash»* and citing a
`file:line` that does it — and there was none to cite. Two mechanisms, one defect, and the
cheaper one fired first. That is the arrangement you want; it is not evidence that the
expensive one is redundant.

**One more thing this phase says about the gates, which is not comfortable.** Every gate
was green on `5da337e` except the one assertion. Gate 3a captured the results screen and
Gate 3a's visual diff passed — because the demo fixture's gated round rendered exactly as
its baseline did, since nothing had changed on that screen. **A screenshot gate cannot see
a surface that was never built.** It compares what exists to what existed.

## 8. What Tor should look at personally, weakest first

1. **§ 5's rule, and whether it is a rule or a mood.** *"A test that fails because your own
   change altered the contract is not a stale test."* I believe it and I acted on it, but I
   cannot check it from inside: the counterfactual — that I would have shipped both defects
   had I updated the assertion mechanically — is a claim about a version of the phase that
   did not happen. **What is checkable is the shape of the fix, and it is in the diff:**
   `M:0053` exists because someone asked what a number counted, not because a test asked
   for a different value.

2. **D103 changes bundle copy on a decision's authority.** It is the first time a v1 phase
   has done that. The reasoning is in § 6 and I think it is right, but the general form —
   *a confirmed decision may rewrite a sentence the bundle sets, when the sentence
   describes behaviour the decision changed* — is broader than one note under one panel and
   is not written down anywhere as a rule.

3. **The gated and ungated arms of `TrendPoint` now differ in shape, and `n` sits outside
   the union.** That is the honest model of what the database returns, but it means
   `isGated(p)` no longer tells a reader everything about what `p` carries. Every other
   cell type in `lib/results/types.ts` keeps the older `{n, avg} | Gated` shape, so the
   file now has two conventions in it, deliberately.

4. **No capture state covers a gated round, and adding one is a fixture change I did
   not make.** § 1.4 verified the clause by hand instead. The demo seed has no
   multi-round survey below the threshold, so Gate 3a photographs this panel only in its
   ungated form — which is why defect 5 could sit behind a green visual diff. Adding the
   fixture is one seed row and one manifest state; it is not in this phase because the
   phase was closing, and it is the kind of thing that should be a decision rather than a
   reflex.

5. **Defect 6 was live in `M:0050` for three commits and no gate saw it.** The fixtures
   are why: every existing arrangement has each respondent answer every question, so
   participation and scale-answerers coincide in all of them. **A fixture family that is
   uniformly "complete" cannot find a denominator bug.** I added the one arrangement that
   breaks the symmetry; I did not audit whether other functions have the same blind spot.

6. **D102 is still unanswered and this is its second phase of waiting.** The scope query is
   one statement against prod. If you would rather I ran it than kept asking, say so and I
   will, and the recommendation resolves the same session.
