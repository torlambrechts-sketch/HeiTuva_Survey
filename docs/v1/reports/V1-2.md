```
ok   Q43 AUDIT: meta carries only the closed set of keys  rows,format,survey_id
ok   Q43 AUDIT: a leser reads none of it                  leser sees 0 of 2 existing rows
```

**Two statuses, deliberately different.** Another organisation gets **404** — the URL
must not confirm the id is real. A leser in the *same* organisation gets **403** — the
survey is in their own list, so hiding its existence would be a lie they can disprove
by looking; what they may not have is the named data. The handler can tell those apart
honestly because step 1 reads `surveys` as the viewer, so RLS has already answered
"does this exist for you" before the RPC is asked anything.

**The route adds no privilege.** There is no service client in the file. It calls
`attributed_results` through the cookie-bound anon client, so RLS and the RPC's own
organisation and role checks are what refuse.

**The audit clause is asserted on the STORED ROW**, read back out of `audit_events`,
not on the object handed to `audit()` — those diverge the moment a column gains a
default or a trigger enriches the row, and the property is about what is *in* the
table. Three assertions plus a closed key set, which is the half a substring scan
cannot do: a new key holding new content would pass a scan on the day it is introduced
and every day it stays empty in the fixture. The answer strings are read from the
database rather than repeated from the seed, so the check keeps covering the survey
when a question is added.

### 1.4 D94 — `surveys.target`

`tests/db/policy-panel.test.ts`, 14 tests. The decision, stated because it was asked
for explicitly: **the LATEST round's recipient count.**

Threshold 5, round 1 sent to 40, round 2 to 4. A survey-level number that stayed at 40
— whether because it was the first or because it was the biggest — is silent in exactly
the case the rule exists for. A sum (44) is worse: nobody will ever compare it with a
threshold, because the threshold is applied **per round**
(`aggregate_results(p_survey, p_group, p_round)`), so the count that has to clear it is
the round's.

The test asserts that in both directions. "Latest" and "largest" agree on every fixture
where rounds grow and disagree only here, so it asserts **40 and 44 are wrong** as well
as that 4 is right — otherwise a later "use the biggest" reading would pass quietly.

**A trigger, not the Send action.** Recipients reach a round by the import, the
single-recipient control, the group expansion, the seed and the test factories. An
action-level writer covers the path it is written in and misses the others silently —
which is the shape of the bug being fixed, not a different one. Same argument as Q36's
ceiling: a rule about a column belongs to the column. Statement-level with transition
tables, so an import of 400 recipients recomputes once rather than 400 times.

Two edges decided with it: a round with no recipients does not move the number (so
creating round 2 does not blank what round 1 earned), and emptying a round falls back
to the previous round rather than to 0 — 0 means "nobody chosen yet" to
`policyWarnings`, and a survey that has been sent is not in that state.

The rule got its second home at the same time: `SendScreen` computes it from `reach`,
the recipients being chosen right now, through the same `policyWarnings` the Builder's
panel and readiness list use.

front of one is what found the first four.

| # | Severity | Defect | Fix |
|---|---|---|---|
| 1 | **blocker** | Four SECURITY DEFINER functions returned `{n: null, avg: null}` at k = 0; every attributed results page 500'd with a digest and no message | migrations 0041, 0042 |
| 2 | major | A leser saw «0 av 0 virksomheter har svart» — four fabricated cards built from the empty array a refusal flattens to | D98, stated refusal |
| 3 | major | Mobile: supplier names truncated to «Ber…»; filter chips ran off the card edge (a RESPONSIVE.md blocker) | `basis-[calc(100%-34px)]`, `flex-wrap` |
| 4 | major | `verify:respondent` selected "the oldest open round in the database" and asserted the anonymity banner on an attributed fixture | selector names every property it asserts |
| 5 | major | `verify:send` never reached the SMS job — `--once` drains one batch and the batch is ten | drain until empty |
| 6 | minor | `verify:roundtrip` left a group in the demo organisation every run; it surfaced in a V1-2 capture as «Gruppe 1788725988772 · n<5» | the probe deletes what it created |
| 7 | minor | The rounds panel's bars came out equal — a percentage height on a flex item beside three text rows gets shrunk to fit | the bar is sized against its own track |

### Defect 1 in full

Four functions built a result cell as:

```sql
case when coalesce(st.n, 0) >= v_k then {n, avg} else {insufficient_data} end
```

The `coalesce` exists to treat "no stats row" as zero, and at every threshold this
schema has ever had that landed in the else arm (`0 >= 3` is false). At **k = 0** —
which `app.k_for` returns for an organisation survey, because attribution is the point
— it reads `0 >= 0`, so a group or round or cell with *nothing in it* took the "here is
your number" branch and emitted `{"n": null, "avg": null}`.

`lib/results/types.ts` says in as many words that there is no third state where `avg` is
present but meaningless. The database was producing exactly that, and the screen called
`.toFixed` on it.

**Not a disclosure bug** — the else arm withholds, so the wrong branch showed NULL
rather than someone's data. It is a correctness and availability bug, fixed in the
database because the shape is the database's promise.

0041 fixed the two the crash came through (`results_summary`, `get_trends`). Fixing a
defect without looking for its siblings is how the second one is found by a customer,
so the live catalogue was swept:

```sql
pg_get_functiondef(p.oid) ~ 'coalesce\([a-z_.]+, *0\) *>= *v_k'
```

Two more, both reachable: `get_benchmarks` (v_k straight from `app.k_for`, so 0 on every
organisation survey — and the results page reads benchmarks for each survey it opens)
and `get_heatmap` (`max(app.k_for(...))`, which is 0 when every selected survey is
attributed). 0042 fixed those. `dashboard_summary` has the same variable but compares in
a `WHERE`, where a null `n` filters the row out — it is fine and was left alone.
Re-swept afterwards: **zero matches.**

The first version of the test **passed against the broken function**, because every
group in the fixture had a stats row and the `coalesce` was never exercised. It now
arranges the cell that matters — a second group nobody answered for, a second round
nobody answered.

## 3. Deviations logged

Appended to `docs/DEVIATIONS.md`:

- **D96 — the CSV's format is decided, because the bundle has none.** The v1 bundle
  draws the «Eksporter CSV» button but its handler is a toast, so there is no file to be
  pixel-perfect to. Semicolon (Norwegian Excel's list separator, and the app's own
  importer already accepts it), a UTF-8 BOM (without it Excel renders æ ø å as mojibake),
  CRLF (RFC 4180). Two behaviours that are not merely serialisation: a field beginning
  `=`, `+`, `-` or `@` is prefixed with a single quote, because spreadsheets evaluate
  such a cell and respondent free text is exactly the untrusted input a formula
  injection needs; and `responded_at` is written as a date rather than a timestamp,
  which is editorial — the hour-truncation rule governs anonymous responses and does not
  reach an attributed row.
  **Checked, with its limit:** an exported file re-imports its addresses and rejects
  nothing, but not the supplier names — the register heads that column «Virksomhet» and
  `HEADER_NAME` has no synonym for it.
- **D97 — Q43's stated reason is one step off.** The decision line says an audit row
  carrying answer text would put respondent content "into a table `leser` can read".
  `audit_events` is not readable by a leser: `audit_sel` (`M:0008:190`) admits
  administrators only, which the gate now asserts directly (a leser session reads 0 of
  the 2 rows that exist). The clause is kept and the property is unchanged, because the
  two real reasons are at least as strong: CLAUDE.md invariant 7 keeps respondent free
  text out of logs and analytics, and the table is append-only (`M:0007:38`) — a row
  that captured an answer could never be corrected or removed while the organisation
  exists. Recorded rather than silently rewriting the rationale, because a decision's
  stated reason is part of the decision.
- **D98 — a leser opening an organisation survey gets a refusal, not four zeros.**
  Neither bundle draws this state, because the prototype has no roles.

## 7. The pattern this phase kept finding

Four checks in one phase believed they were exercising something they were not:

| # | Check | What it believed | What it actually got |
|---|---|---|---|
| 1 | Q30 fixture | a section refused for scope | a document with no sections — the share had no group, so it was refused earlier |
| 2 | Q43 audit | three properties of the stored row | `.every()` over an empty table — vacuously true |
| 3 | `verify:respondent` | the demo anonymous survey | the oldest open round anywhere, an attributed fixture in another org |
| 4 | `verify:send` | the queue drained | one batch of ten, with the SMS job still in it |

The standing question written into `tests/db/clients.ts` after V1-1 covers 1 and 2:
*what else could refuse this — or satisfy it — before my check gets a chance?*

Numbers 3 and 4 are a different half of the same thing, and it is **not** written down
anywhere yet: *what else could have moved the state my selector assumes?* Both picked
the wrong row by ordering rather than by logic, and both had been fragile long before
this phase — V1-2's fixtures only changed which row was oldest and how full the queue
was. Writing that down is a change to the verification apparatus, which is frozen, so
it is raised here for a decision rather than made.

## 8. Post-acceptance (2026-09-06)

V1-2 accepted. Four things changed after the report was written; they are recorded
here rather than rewriting the sections above, so the report stays a record of what
was true when it was submitted.

1. **Both standing questions now live in `tests/db/clients.ts`.** The freeze is on
   new gates — machinery that executes, can fail and needs maintaining — and a
   comment beside one that already exists adds nothing that runs. The second half:
   *what could have moved the state my selector assumes?*, with `verify:respondent`
   and `verify:send` written out as its two instances, plus the converse (do not
   become what else exists) and the positive form of the first question (what could
   SATISFY this assertion).
2. **The CSV's «E-post» column is gone** (§ 6.1 of the review). A supplier register
   export is a legal artefact; an address is administrative data that leaves the
   organisation the moment the file is forwarded. Asserted as a property over the
   whole file, at unit level and at the route. Consequence recorded in D96: the
   export no longer round-trips through the import step at all (0 rows, 3 rejected,
   measured), which retires carried finding 4.
3. **D98's copy stands, and is now provably data-independent.**
   `tests/unit/refusal-copy.test.ts` asserts that four refusal messages carry no ICU
   placeholder in either language — a string with no `{…}` cannot vary whatever the
   caller passes, which proves it for every data shape rather than the two a render
   would happen to try. A positive control keeps it honest: `results.insufficient`
   DOES carry the threshold, because Q17 requires the promise to track the setting
   or it lies. Mutation-checked in both directions.
4. **The `resAttrib`/`resAggregate` switch is logged OPEN as D99**, not settled.
   Removing the aggregate half is right for the primary case; if a customer asks
   «how many of our 200 suppliers have a whistleblowing channel», the answer is a
   section over the roles the pack already designates — not a restored screen half,
   which would bring back the group breakdown, the trend of averages and the themes,
   none of which mean anything on a supplier survey.
